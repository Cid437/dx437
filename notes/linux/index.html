What is an operating system / kernel?

An operating system (OS) is system software that manages computer hardware and software resources and provides common services for programs. The kernel is the core component of the OS — it manages the CPU, memory, and I/O devices, and acts as the bridge between applications and the hardware through system calls.

Timeline: Unix → GNU → MINIX → Linux

  • 1969 — Unix is developed by Ken Thompson and Dennis Ritchie at AT&T Bell Labs (first released 1971; rewritten in C in 1973).
  • 1977 — UC Berkeley releases BSD, a free Unix-like system.
  • 1983 — Richard Stallman starts the GNU ("GNU's Not Unix") project to build a free Unix-like OS. Its kernel, Hurd, never attracted enough developers, leaving GNU without a kernel of its own.
  • 1987 — Andrew S. Tanenbaum releases MINIX, a Unix-like system intended for academic use; the source was viewable but modification/redistribution were restricted.
  • 1991 — Linus Torvalds releases the Linux kernel (v0.01, developed as a cross-development project under MINIX; publicly announced/released September 17, 1991), which was soon combined with GNU tools to form a complete OS — hence "GNU/Linux."
Order to remember: Unix (1969) → BSD (1977) → GNU project started (1983) → MINIX (1987) → Linux kernel (1991). MINIX was built for academic use, not Linux.

Kernel types

Kernels are classified by how much runs in kernel space vs. user space:

  • Monolithic kernel — all OS services run in kernel space (best performance, more complex). Examples: Linux, Unix, OpenVMS.
  • Microkernel — minimal services in kernel space, rest in user space (more stable, more context switches). Examples: Mach, L4, MINIX.
  • Hybrid kernel — combines monolithic speed with microkernel modularity. Examples: Windows NT kernel, and the Darwin/XNU kernel used by macOS and iOS (built on the Mach microkernel plus BSD components).
  • Exokernel — exposes hardware resources directly to applications with minimal abstraction (e.g., Nemesis).
  • Nanokernel — hardware abstraction with essentially no system services (e.g., EROS).
Linux's kernel is monolithic. Windows (NT kernel) and macOS/iOS (Darwin/XNU) are both hybrid kernels.

Linux architecture (user space vs. kernel space)

User applications and libraries (like glibc) run in user mode and talk to the kernel through the system call interface. The Linux kernel itself runs in kernel mode and contains subsystems for process scheduling, memory management, IPC, virtual files, and networking, sitting directly above the hardware.

Shells

A shell is a program that interfaces between the user and the kernel — it takes commands, passes them to the kernel, and displays the output.

  • Bourne shell (sh) — /bin/sh, the original Unix shell by Steve Bourne; no built-in arithmetic or command history.
  • Bash (GNU Bourne-Again shell) — /bin/bash, Bourne-compatible with command recall/editing; the common Linux default.
  • C shell (csh) — /bin/csh, created by Bill Joy at UC Berkeley; C-like syntax and command history.
  • Korn shell (ksh) — /bin/ksh, by David Korn at AT&T; a superset of the Bourne shell.
  • Z shell (zsh) — /bin/zsh, highly customizable, plugin/theme support.

By default, the root user's prompt ends in # while a regular user's prompt ends in $ (or % for csh).

File systems

The MINIX file system was Linux's first file system, inherited from its cross-development under MINIX. It was mostly bug-free but limited to a 64MB maximum size and 14-character filenames.

  • ext (1992) / ext2 (1993) — created chiefly by Rémy Card. ext2 has no journal, which is exactly why it's still favored for flash media (SD cards, USB drives): fewer writes, better endurance.
  • ext3 (2001) — adds journaling on top of the ext2 design.
  • ext4 (2009) — successor to ext3; supports larger volumes/files and can optionally run journal-less.
  • Btrfs (2009) — copy-on-write file system aimed at fault tolerance and large-scale storage.
  • ReiserFS (2001) — journaling file system, formerly the default on SUSE.
  • Windows uses FAT, NTFS, exFAT, and ReFS instead — plain FAT (like ext2) also has no journal.
If asked "which file system does not use journaling," think ext2 (or FAT) — journaling was introduced with ext3.

The Linux directory structure (FHS)

  • / — the root of the entire file system.
  • /bin — essential command binaries needed for minimal functionality, booting, and repairing the system (e.g., cat, ls, cp), available to all users.
  • /sbin — essential system binaries, mainly for the root user (e.g., fsck, init, route).
  • /etc — host-specific, static configuration files for the system (historically "etcetera"; may not contain binaries).
  • /boot — boot loader files (kernel images, initrd).
  • /dev — device files.
  • /home — regular users' home directories; /root is the home directory of the root user specifically.
  • /lib, /lib64 — libraries needed by /bin and /sbin.
  • /mnt, /media — mount points for file systems and removable media.
  • /opt — add-on application packages.
  • /proc, /sys — virtual file systems exposing kernel/process/device information.
  • /tmp — temporary files, often cleared on reboot.
  • /usr — secondary hierarchy of shareable, read-only user resources (/usr/bin, /usr/lib, etc.).
  • /var — variable data that changes during operation (logs, spool files, mail).
Quick pair to remember: /etc = configuration files. /bin = essential executable binaries.

Package managers by distribution

  • Debian / Ubuntu — .deb packages via apt / apt-get / dpkg.
  • Arch Linux — .pkg.tar.zst packages via pacman (e.g., pacman -S package, pacman -Syu to sync and upgrade).
  • Fedora — .rpm packages via dnf (the successor to yum).
  • CentOS / RHEL — .rpm packages via yum.
  • openSUSE — packages via zypper.
Arch Linux's defining package manager is pacman.

Boot loaders

GNU GRUB (GRand Unified Bootloader) is the boot loader used by most Linux distributions today; it lets a system choose between multiple installed OSes or kernel configurations. LILO (Linux Loader) was the older default before GRUB took over, and its development stopped in 2015.

Distributions (distro)

A Linux distribution packages the kernel with supporting software (much of it from the GNU project) for desktop or server use. Well-known examples include Debian, Ubuntu (based on Debian), Fedora and CentOS (RPM-based, tied to Red Hat), SUSE, Slackware, Gentoo, and Arch Linux. Android is also Linux-kernel-based.

Users: root vs. regular users

The root user is the Linux superuser, with unrestricted administrative access to the whole system; its home directory is /root. Regular users have their own home directories under /home and need elevated privileges (e.g., via sudo or the su command) to perform administrative tasks.
