Linux v2 — Commands, Networks & Servers

Permissions, sudo users, network configuration, package installation, and server services — the practical side of Linux administration, matching the Linux v2 quiz.

File ownership

Every Linux file has an owner and belongs to a group. Access is defined separately for three classes:

  • User (u) — the owner. By default, whoever creates a file owns it.
  • Group (g) — a group can contain many users; every member gets the same group permissions.
  • Other (o) — anyone who is neither the owner nor in the file's group.
  • All (a) — all three at once (same as ugo).

File permissions

  • Read (r) — open and read a file. On a directory: list its contents.
  • Write (w) — modify a file's contents. On a directory: add, remove, and rename files inside it.
  • Execute (x) — run a file as a program. Unlike Windows (.exe), Linux will not run a file unless execute is set, even if you can read and write it.

Reading ls -l

-rw-r--r--  1 alice users  2321 Mar 15  notes.txt
drwxr-xr-x  2 alice users  1024 Jan 25  Xfonts
  • 1st character = type: - file, d directory, l symbolic link.
  • Next 9 characters = three sets of rwx for owner, group, other (in that order).
  • Then: number of hard links, owner, group, size in bytes, last-modified date, name.

chmod — change mode

Syntax: chmod <options> <permissions> <file/dir>. It works in two modes.

Absolute (numeric) mode

Add up the values for each class: r = 4, w = 2, x = 1, none = 0.

rwx = 4+2+1 = 7
r-x = 4+0+1 = 5
r-- = 4+0+0 = 4

chmod 754 file       # owner rwx, group r-x, other r--
chmod 644 file.htm   # owner rw-, group r--, other r--
chmod 666 file.txt   # everyone rw-
chmod -R 755 itemsDir   # -R = recursive (directory and everything inside)

Symbolic mode

Classes: u user, g group, o other, a all. Operators:

  • + adds the specified modes
  • - removes the specified modes
  • = sets the modes to exactly what you specify
chmod u=rwx,g=rx,o=r file     # same as 754
chmod u=rw image.jpg
chmod o-wx netconfig.conf     # remove write+execute from others
chmod o+r fileName            # give others read
chmod u+x run.sh              # make a script runnable by its owner
chmod 774 netconfig.conf → owner rwx, group rwx, other r--. Quick memory trick: 7 = everything, 6 = read+write, 5 = read+execute, 4 = read only.

chown — change ownership

Changes the owner and/or group of files and directories. Usually needs sudo.

sudo chown mike file.txt                  # owner only
sudo chown alice file1 file2 file3        # several files
sudo chown bob file*                      # wildcard
sudo chown alice:admins file1 file2       # owner:group
sudo chown -R alice:alice Documents       # -R = recursive
chown --from=root:staff bob:root file1    # only change if current owner:group match

Creating a sudo user

  1. Log in as root.
  2. Add the user: adduser newuser (or useradd newuser).
  3. Add them to the sudo group: usermod -aG sudo newuser — the -a means append; without it the user is removed from their other groups.
  4. Verify: getent group sudo (should list the user).
  5. Use it: su - newuser, then sudo ls -al /root.

Sudo privileges are defined in /etc/sudoers. Always edit it with visudo (it checks syntax so you can't lock yourself out). The default editor can be changed: EDITOR=nano visudo.

Hosts file & hostname

  • /etc/hosts — plain-text file used to translate hostnames into IP addresses, and to give easy names to machines on a small home/office network. Edit with sudo nano /etc/hosts, e.g. 127.0.0.1 new-hostname.
  • /etc/hostname — stores the computer's name.
hostname                              # show the current name
sudo nano /etc/hostname               # permanent (edit file)
sudo hostname new-hostname            # temporary, no restart needed
hostnamectl set-hostname 'my-laptop'  # set via systemd

ifconfig / iwconfig / ip

  • ifconfig = "interface configuration" — view and change network interface settings.
  • iwconfig — like ifconfig, but for wireless interfaces only.
  • ip address / ip a — the modern way to view interface addresses.
sudo ifconfig eth0 192.168.100.100/24
sudo ifconfig enp0s3 192.168.100.100 netmask 255.255.255.0
sudo route add default gw 192.168.0.253 eth0
route -n          # show the kernel IP routing table (numeric)
You need root/administrator rights to change an IP address. Changes made with ifconfig are temporary — they only last for the current session. Setting an IP manually also means you are leaving DHCP for static addressing.

Netplan (Ubuntu Server 18.04+ / 22)

Config file: /etc/netplan/00-installer-config.yaml. Edit it, save (Ctrl+O), exit (Ctrl+X) in nano, then apply with sudo netplan apply.

DHCP (automatic address)

network:
  version: 2
  renderer: networkd
  ethernets:
    enp3s0:
      dhcp4: true

Static address (Ubuntu Server 22)

network:
  version: 2
  ethernets:
    enp0s3:
      dhcp4: no
      addresses:
        - 192.168.1.200/24
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses:
          - 8.8.8.8
          - 8.8.4.4
Older examples use gateway4: 192.168.1.1 for the gateway. Newer netplan versions deprecate it in favour of routes with to: default and via. YAML is indentation-sensitive — use spaces, never tabs.

Network files on Debian & Ubuntu (ifupdown)

Older systems use /etc/network/interfaces (create it if missing):

iface eth0 inet static
address 192.168.0.2
netmask 255.255.255.0
gateway 192.168.0.1

Edit with sudo nano (Ctrl+O save, Ctrl+X exit) or sudo vim (:w save, :q quit). Then restart networking:

sudo systemctl restart networking.service
sudo /etc/init.d/networking restart     # or stop / start
ifup eth0      # bring one interface up
ifup -a        # bring all interfaces up
ifdown -a      # take all interfaces down
ip a           # verify the result

What is a server?

A server is hardware or software that provides functionality (services) to other programs or devices called clients. This is the client–server model, usually implemented as request–response: the client sends a request, the server performs an action and sends back a response. One server can serve many clients, and one client can use many servers.

  • Any computer can be a server — what separates a server from a workstation is the function it performs, not the hardware (though servers usually have more RAM and robust 24/7 operating systems).
  • Network servers became common in the early 1990s, when PCs began providing services formerly hosted on mainframes and minicomputers.

Common server types & Linux software

  • Web server — Apache, Nginx, LiteSpeed, lighttpd (serves content over HTTP)
  • Database server — MySQL, MariaDB, PostgreSQL, MongoDB, DB2
  • DNS server — BIND9 (translates domain names to IP addresses)
  • DHCP server — isc-dhcp-server (hands out IP addresses automatically)
  • File server — Samba (Windows-compatible sharing) · FTP server — vsftpd; clients include FileZilla and WinSCP
  • SSH server — OpenSSH; clients include PuTTY, SecureCRT, MobaXterm
  • Mail server — Sendmail, Postfix, Zimbra
  • Proxy server — Squid, Tiny Proxy, Privoxy (sits between a client and an external server to filter requests, improve performance, and share connections)
  • Print server — CUPS (Common UNIX Printing System)
  • Others: application (middleware between database and user), collaboration, list, virtual, game, real-time communication (IRC), Telnet servers.

Microsoft platforms (for comparison): Exchange (email/calendar), Lync (real-time communications), SharePoint (collaboration), SQL Server (RDBMS), IIS (web), and Hyper-V (Type-1 hypervisor).

Installing software

  • GUI tools: Ubuntu Software Center, Software Manager (Linux Mint), Synaptic Package Manager.
  • Downloaded software: proprietary installers, third-party repositories, or unpacking a binary archive.
  • Terminal: apt install / apt-get install (Debian/Ubuntu), yum / dnf (Red Hat family), pacman -S (Arch), dpkg and rpm (low-level package files), pkg install (BSD), slackpkg / slapt-get (Slackware).
  • tasksel — a Debian/Ubuntu tool that installs several related packages together as one "task" (e.g. web server, DNS server, print server). It is used during installation but can be run any time.
  • Windows software on Linux: Wine ("Wine Is Not an Emulator") is a compatibility layer; or use a virtual machine (VirtualBox, VMware, Virtual PC, Red Hat Virtualization).

Web server — the LAMP stack

LAMP = Linux + Apache + MySQL + PHP: open-source software installed together to host dynamic websites and PHP web apps. Site data lives in MySQL; PHP processes dynamic content.

# Step 1 — Apache
sudo apt update
sudo apt upgrade
sudo apt install apache2
sudo ufw app list
sudo ufw allow in "Apache"
sudo ufw status

# Step 2 — MySQL
sudo apt install mysql-server
sudo mysql_secure_installation
sudo apt install phpmyadmin

# Step 3 — PHP
sudo apt install php libapache2-mod-php php-mysql

# Step 4 — site folder
sudo mkdir /var/www/test_app/

# Step 5 — test in a browser
http://IP_address/test_app

UFW Apache profiles

  • Apache — opens only port 80 (normal, unencrypted web traffic)
  • Apache Full — opens port 80 and port 443 (TLS/SSL encrypted)
  • Apache Secure — opens only port 443

SSH server

SSH (Secure SHell) is a cryptographic network protocol for operating network services securely over an unsecured network — typically remote login and remote command execution. Standard TCP port: 22.

sudo apt update
sudo apt install openssh-server
sudo systemctl status sshd
sudo ufw allow ssh
ssh username@ip_address

# key-based login
ssh-keygen -t rsa
ssh-copy-id user@ssh-ip-address

FTP server (vsftpd)

sudo apt update && sudo apt install vsftpd
sudo service vsftpd status

# firewall
sudo ufw deny 20/tcp
sudo ufw allow 21/tcp     # FTP
sudo ufw allow 22/tcp     # SSH

FTP (File Transfer Protocol) is one of the oldest Internet services, used to move files between computers. Port 21 is the FTP control port.

DHCP server (dhcpd)

Example plan: network 192.168.100.0, server IP 192.168.100.100, netmask 255.255.255.0, lease range 192.168.100.101 – 192.168.100.200 (100 addresses).

sudo apt install isc-dhcp-server -y      # ISC = Internet Systems Consortium
sudo nano /etc/dhcp/dhcpd.conf
authoritative;     # the only (official) DHCP server on the network

subnet 192.168.100.0 netmask 255.255.255.0 {
  range 192.168.100.101 192.168.100.200;
  option domain-name-servers 192.168.100.1;
  option routers 192.168.100.2;
}
sudo systemctl restart isc-dhcp-server.service   # apply changes
dhcp-lease-list                                  # test: see leased clients

Fixed (reserved) IP for one machine

host web-server {
  hardware ethernet 00:0c:29:c3:a0:1b;
  fixed-address 192.168.100.9;
}

Starting, stopping & restarting services

Two officially adopted methods:

# systemctl (CentOS, Ubuntu, Red Hat, Fedora, Debian, and more)
sudo systemctl start httpd
sudo systemctl stop httpd
sudo systemctl restart httpd

# service
sudo service httpd start
sudo service httpd stop
sudo service httpd restart
httpd is the Apache service name on Red Hat–family systems; on Debian/Ubuntu it is apache2.

Quick cheat sheet

  • Change permissions → chmod · change owner → chown
  • Add to sudo → usermod -aG sudo user · edit sudoers → visudo
  • Hostname file → /etc/hostname · name-to-IP map → /etc/hosts
  • Netplan → /etc/netplan/00-installer-config.yaml then sudo netplan apply
  • Old-style network file → /etc/network/interfaces
  • Ports: SSH 22 · FTP 21 · HTTP 80 · HTTPS 443
  • DHCP config → /etc/dhcp/dhcpd.conf · service → isc-dhcp-server
